# 第 4 课 · 应付全流程（AP）：进项票、付款核销与 AR/AP 的对称美

> 覆盖业务：#3 索尼采购、#4 付索尼 50%、#6 瑞萨采购、#10 付瑞萨全款
> 目标：把第 3 课的知识镜像到应付侧；理解进项税；掌握"收票 → 付款 → 核销"链路。**AP 和 AR 是同一套逻辑的两个方向，学完这课你会对"模块复用"有体感。**

---

## 一、业务场景

**场景 A（3 月 3 日）**：从索尼半导体采购 200 片 CMOS 图像传感器（视觉系统的核心部件），850 元/片（不含税），货和发票同时到，约定 30 天内付款。

**场景 B（3 月 8 日）**：公司资金安排，先付索尼一半货款。

**场景 C（3 月 12 日）**：从瑞萨电子采购 1,000 颗 MCU，32 元/颗，货到票到。

**场景 D（3 月 25 日）**：瑞萨货款到期，全额付清。

## 二、为什么有这个东西

### 2.1 AP 是 AR 的镜像

第 3 课的所有概念直接对称过来：

| AR（应收） | AP（应付） |
|-----------|-----------|
| 我开发票给客户（Sales Invoice） | 供应商开发票给我（Purchase Invoice） |
| 客户欠我钱 → 应收账款（资产） | 我欠供应商钱 → 应付账款（负债） |
| 我收款核销发票 | 我付款核销发票 |
| 发票 Outstanding = 客户还欠我多少 | 发票 Outstanding = 我还欠供应商多少 |
| 逾期 → 我去催收 | 逾期 → 影响我的信用 |

**既然逻辑对称，代码为什么不复用？**——Frappe Books 正是这么做的：`SalesInvoice` 和 `PurchaseInvoice` 都继承 `Invoice` 基类，`Payment` 一张单据用 `type = Receive/Pay` 区分方向。你们公司的 AR/AP 模块如果完全两套代码，值得想想这个设计。

### 2.2 进项税：采购环节替自己"垫付"的税

第 2 课讲过：采购付的钱里有一部分是**进项税**（22,100 元），它不是成本，是可以从销项税里抵扣的"垫付款"。所以采购发票的分录要把税额单独拆出来挂到 `Input Tax` 科目，月底申报增值税时：

```
应交增值税 = 销项税合计 − 进项税合计 = 138,502 − 26,260 = 112,242 元
```

如果你们系统把进项税混进采购成本里，财务月底就要手工剔税——这就是"系统替财务干活"和"财务替系统擦屁股"的分水岭。

### 2.3 为什么付款也要核销

和收款完全同理：付索尼 96,050 元，必须明确**付的是哪张发票**，否则"我还欠索尼多少钱"无从算起。核销后 PINV-2026-001 变为 `Partly Paid`，未清 96,050——这笔余额会一直提醒财务"还有一半没付"，直到 4 月初付清。

## 三、财务在干嘛

### 场景 A：收到索尼发票（3 月 3 日）

```
借：库存商品/主营业务成本    170,000     （本课程简化：直接进成本，第 7 课说明）
借：应交税费-进项税           22,100     （可抵扣的垫付款，资产）
  贷：应付账款-索尼           192,100    （欠供应商的钱，负债）
```

注意方向：**两个借方、一个贷方**。借贷可以一对多，只要合计相等。

### 场景 B：付索尼 50%（3 月 8 日）

```
借：应付账款-索尼             96,050     （负债减少记借方）
  贷：银行存款                 96,050
```

### 场景 C：收到瑞萨发票（3 月 12 日）

```
借：主营业务成本               32,000
借：应交税费-进项税             4,160
  贷：应付账款-瑞萨             36,160
```

### 场景 D：付瑞萨全款（3 月 25 日）

```
借：应付账款-瑞萨             36,160
  贷：银行存款                 36,160
```

核销后 PINV-2026-002 状态 `Paid`，瑞萨应付清零；索尼还剩 96,050 挂着。

## 四、动手操作

### 4.1 录入 PINV-2026-001（索尼）

1. **Purchases → Purchase Invoice → New**
2. Supplier 选 `索尼半导体解决方案（上海）有限公司`，Date `2026-03-03`
3. 明细行：Item `CMOS 图像传感器`——**注意**：我们没把这个原材料放进商品库（Item.csv 都是卖的产品）。两种处理方式：
   - 推荐：直接在发票明细行手工填名称 `CMOS 图像传感器`、数量 `200`、单价 `850`（Frappe Books 允许非库商品行）
   - 或：先在 Item 里新建一个 `CMOS 图像传感器`（itemType = Product, rate = 850）再选用
4. Tax 选 `增值税-进项 13%`，核对：不含税 170,000 + 进项税 22,100 = **192,100.00**
5. Save → Submit

### 4.2 付索尼 50%

1. **Purchases → Payment → New**
2. Type `Pay`，Party `索尼半导体`，Date `2026-03-08`，Amount `96050`
3. 给 PINV-2026-001 分配 `96,050`，Save → Submit
4. 回到发票确认：状态 **Partly Paid**，Outstanding **96,050.00**

### 4.3 录入 PINV-2026-002（瑞萨）并全额付款

1. Purchase Invoice：Supplier `瑞萨电子（中国）有限公司`，Date `2026-03-12`，明细 `MCU` × 1,000 @ 32，Tax `增值税-进项 13%`，合计 **36,160.00**，Submit
2. Payment：Type `Pay`，Date `2026-03-25`，Amount `36160`，全额分摊，Submit
3. 确认发票状态 **Paid**

## 五、代码导读

| 文件（相对 `vendor/frappe-books/`） | 看点 |
|------|------|
| `models/baseModels/Invoice/Invoice.ts` | 同一个基类，销售/采购两个子类——观察它如何按方向翻转借贷（销售借应收，采购贷应付） |
| `models/baseModels/PurchaseInvoice/PurchaseInvoice.ts` | 采购发票特化 |
| `models/baseModels/Payment/Payment.ts` | `type: Receive | Pay` 一张单据两个方向——你们系统如果分"收款单表"和"付款单表"，可以对比下利弊 |
| `models/baseModels/Tax/Tax.ts` | 税额计算引擎：销项/进项只是挂了不同科目的两个 Tax 记录，计算逻辑完全复用 |

## 七、练习

1. 索尼的另一半货款 96,050 约定 4 月 2 日前付。到 3 月 31 日，这笔余额在资产负债表上算"资产"还是"负债"？放在哪个报表项目下？
2. 如果采购的不是原材料而是**一台自用机床**（固定资产），进项税还能抵扣吗？分录的借方会有什么不同？（提示：中国现行政策下固定资产进项税可抵扣，但借方科目不再是成本——查查"固定资产"科目的位置。）
3. 观察 Payment 单据：同一个 `Payment` 模型处理收和付。如果你们系统的业务规则差异很大（比如付款要走三级审批、收款不用），你会选择一张表加类型字段，还是拆成两张表？说说理由。
