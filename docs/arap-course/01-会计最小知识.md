# 第 1 课 · 会计最小知识包：借贷记账法到底在解决什么问题

> 覆盖业务：#1 股东注资 500 万
> 目标：学会三个概念——会计恒等式、借贷记账、科目表；在 Frappe Books 里做出第一笔分录。

---

## 一、业务场景

2026 年 3 月 1 日，基恩士自动化（上海）有限公司注册成立，股东把 500 万元打入公司招商银行对公账户。财务（也就是你）需要在系统里记第一笔账。

**问题来了**：不就是"银行多了 500 万"吗，记一行流水不就行了？为什么要发明"借贷"这么别扭的东西？

## 二、为什么有这个东西

### 2.1 单式记账的死穴

想象你用 Excel 记流水：

| 日期 | 摘要 | 金额 |
|------|------|------:|
| 03-01 | 股东注资 | +5,000,000 |

一个月后你再看到这一行，你无法回答：**这 500 万是哪来的？**是股东投的（不用还）、银行借的（要还）、还是卖货的货款（挣的）？三种来源对公司的意义完全不同，但单式记账把它们混成了一个数字。

更致命的是**无法校验**。数字抄错一位，没有任何机制能发现。

### 2.2 复式记账：每笔业务至少记两笔，方向相反

1494 年意大利人卢卡·帕乔利总结的规则，至今仍是全世界财务系统的底层协议：

> **任何一笔业务，都同时影响至少两个科目；一边记"借"（Debit），另一边记"贷"（Credit），且借贷金额永远相等。**

注资这笔业务：

```
借：银行存款        5,000,000     ← 公司的钱多了
  贷：实收资本      5,000,000     ← 这钱是股东投的（来源）
```

- **借（Dr）**读作"资源去了哪里"
- **贷（Cr）**读作"资源从哪里来"

现在再看账上"银行存款 500 万"，它的来源一目了然：实收资本。而且因为**借方合计 = 贷方合计**是铁律，任何一笔账记错金额，试算时立刻暴露——这就是财务系统自带的数据完整性校验。

### 2.3 会计恒等式：所有报表的源头

```
资产 = 负债 + 所有者权益
```

- **资产**：公司拥有的资源（银行存款、应收账款、库存）
- **负债**：欠外部的钱（应付账款、应交税费）
- **所有者权益**：属于股东的钱（实收资本、累计利润）

注资后：资产（银行存款 500 万）= 负债（0）+ 权益（实收资本 500 万）✓

每一笔分录都在维持这个等式。后面所有课程、所有报表，都是这个等式的展开。

### 2.4 科目表（Chart of Accounts）：钱的分类体系

"银行存款""实收资本"这些名字不是随便起的，它们来自**科目表**——一张树状的分类清单，财务的每一分钱都必须落在某个科目上。科目表就是财务系统的"数据字典 + 枚举约束"：没有科目，就没有分录；没有分录，就没有报表。

## 三、财务在干嘛

财务人员收到银行到账回单后的标准动作：

1. 判断业务性质：股东注资 → 影响"银行存款"和"实收资本"
2. 编制会计分录（如上）
3. 录入系统，生成**凭证**（Journal Entry）
4. 凭证审核过账后，分录进入**总账**（General Ledger）

分录规则速记（零基础够用版）：

| 科目类型 | 增加记 | 减少记 |
|---------|--------|--------|
| 资产（银行存款、应收、库存） | 借 | 贷 |
| 负债（应付、应交税费） | 贷 | 借 |
| 权益（实收资本、利润） | 贷 | 借 |
| 收入 | 贷 | 借 |
| 费用 | 借 | 贷 |

> 不用背。记住"**资产增加记借方**"，其余全部能用恒等式推出来。例如：收钱还债 → 银行存款增加（借），应付账款减少（负债减少记借）……等等，两个借？不对——还债是资产减少（贷）+ 负债减少（借）。自己动手推两遍就内化了，第 3、4 课有大量练习。

## 四、动手操作

> 前置：已完成课程总览页第四节"建库"。

**任务：录入股东注资凭证**

1. 侧边栏 **Common → Journal Entry**，点 **New**（或直接按 `⌘+N`）
2. Entry Type 保持 `Journal Entry`，Date 选 `2026-03-01`
3. 在第一行 Account 里选 `Bank Accounts` 下的银行账户
   - 如果还没有银行账户：先到 **Common → Account → New**，在 `Bank Accounts`（这是科目组）下新建子科目 `招商银行上海分行 8888`，Account Type 选 `Bank`
4. 该行 **Debit** 填 `5000000`
5. 第二行 Account 选 `Capital Stock`（实收资本，位于 Equity 下），**Credit** 填 `5000000`
6. 点 **Save**，再点 **Submit**（提交 = 过账）

**验证**：打开 **Reports → General Ledger**，账户选 `Capital Stock`，应看到一条 5,000,000 的贷方记录。

### 关于 Save 与 Submit（重要概念）

Frappe Books（以及 ERPNext、SAP）的单据都有两层状态：

- **Save（草稿）**：随便改，不产生任何账务影响
- **Submit（过账）**：单据生效，**此时才真正生成会计分录**写入总账，且不可再改

这就是财务系统"操作留痕、过账锁定"的核心设计，第 6 课讲红冲时会看到它的全部意义。

## 五、代码导读

一笔凭证过账时发生了什么？看三个文件（相对 `vendor/frappe-books/`）：

| 文件 | 看点 |
|------|------|
| `models/baseModels/JournalEntry/JournalEntry.ts` | 凭证模型：校验借贷是否平衡（`validate`） |
| `models/baseModels/AccountingLedgerEntry/AccountingLedgerEntry.ts` | 分录台账：过账后每一条借贷记录落到这里，它就是"总账"的物理表 |
| `reports/GeneralLedger/GeneralLedger.ts` | 总账报表：按科目+期间查询 AccountingLedgerEntry |

关键认知：**单据（JournalEntry）和分录（AccountingLedgerEntry）是两张表**。单据是业务输入，分录是财务事实，后者只增不改。你在公司做的发票模块，一定也有类似的分层。

## 七、练习（5 分钟）

3 月 1 日同一天，公司用银行存款支付办公室 3 月房租 35,000 元（计入 `Office Rent` 科目，Indirect Expenses 下）。请思考并录入这笔分录。

<details><summary>参考答案</summary>

```
借：Office Rent（房租费用）   35,000
  贷：招商银行上海分行        35,000
```

费用增加记借方，银行存款减少记贷方。注意：这笔练习会让你的银行余额变成 4,965,000，后续课程的期末核对数字**不包含**这笔练习分录。为保持与课程答案一致，建议跳过本练习，或做完后记住差额。
