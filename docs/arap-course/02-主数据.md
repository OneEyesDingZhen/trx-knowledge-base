# 第 2 课 · 主数据：为什么财务系统先建"字典"再记账

> 覆盖业务：数据导入（Party / Item / Tax）
> 目标：理解主数据（Master Data）的价值；完成客户、供应商、商品、税率的导入，为第 3 课开票做准备。

---

## 一、业务场景

3 月 1 日下午，销售部跑来开票："比亚迪订了 500 个光电传感器，快给我开张发票！"

你打开系统准备开单，发现要填：客户名称、税号、商品名称、单价、税率……如果每张发票都手打一遍"比亚迪精密制造有限公司"，三个月后账上会出现"比亚迪""BYD""比亚迪精密"三个"客户"，应收报表直接报废。

**所以财务系统有个铁规矩：先建主数据，再跑业务。**

## 二、为什么有这个东西

主数据（Master Data）是**变化缓慢、被业务单据反复引用**的基础档案。对应到 AR/AP 领域：

| 主数据 | 在发票上扮演什么角色 | 不统一的后果 |
|--------|---------------------|-------------|
| **Party（客户/供应商）** | 谁买 / 卖给谁，带税号、默认科目 | 应收按客户汇总时一团乱麻 |
| **Item（商品/服务）** | 卖的是什么、默认单价、默认收入科目 | 同一商品多种叫法，销售统计失真 |
| **Tax（税率）** | 含税金额怎么算、税金进哪个科目 | 税额手算出错，申报对不上 |
| **Account（科目）** | 所有钱的最终归宿 | 第 1 课已讲 |

用程序员的话说：主数据就是**被外键引用的维度表**，业务单据是事实表。发票上不存"比亚迪精密制造有限公司"这个字符串，存的是 Party 的主键——这样改名、合并、按客户出报表才可行。

> 你在公司做的开票报表，"group by 客户"能不能跑对，取决于主数据干不干净。这就是为什么要专门有一课讲它。

## 三、财务在干嘛

建账初期，财务（常和 IT 一起）会做这些事：

1. **梳理往来单位**：收集客户/供应商全称、税号、收票信息——税号直接决定发票合不合规
2. **梳理商品目录**：SKU 编码、标准售价、计量单位
3. **确定税率政策**：中国销售工业产品适用 **增值税 13%**；采购取得进项发票同样是 13%
4. **定制科目表**：在标准科目表上补充公司需要的科目（比如按币种分银行账户、区分进项/销项税科目）

### 关于增值税：本课必须懂的 60 秒版本

增值税是**价外税**：发票金额 = 不含税价 + 税额。

- 你**卖出**商品收客户 723,200 元 = 货价 640,000 + **销项税** 83,200（替税务局代收，欠税务局的）
- 你**买入**材料付供应商 192,100 元 = 货价 170,000 + **进项税** 22,100（你垫付的，可以抵扣）
- 月底交给税务局的钱 = 销项税 − 进项税

所以系统里要建**两个税科目**：`Output Tax`（销项，负债类）和 `Input Tax`（进项，资产类/抵减项）。它们互不相干，分别记录代收和垫付。

## 四、动手操作

> 配套 CSV 在 [arap-finance-course 仓库](https://github.com/OneEyesDingZhen/arap-finance-course) 的 `data/` 目录下，先下载到本地。

### 4.1 先补两个税科目（手工，2 分钟）

导入税率前，`Output Tax` 和 `Input Tax` 这两个科目必须存在：

1. **Common → Account → New**
   - Name：`Output Tax`，Parent Account：`Duties and Taxes`（在 Current Liabilities 下），Account Type：`Tax`，保存
2. 再建一个：
   - Name：`Input Tax`，Parent Account：`Tax Assets`（在 Current Assets 下），Account Type：`Tax`，保存

> 思考：为什么销项税放在"负债"下、进项税放在"资产"下？（答案：销项是替税务局代收、早晚要交出去的钱 → 负债；进项是可以抵扣/收回的钱 → 资产。）

### 4.2 导入客户与供应商

1. 侧边栏 **Common → Import Wizard**
2. 选择数据类型 **Party**，上传 `data/Party.csv`
3. 映射确认无误后执行导入，应成功导入 **8 条**：4 个 Customer（比亚迪、宁德时代、立讯、富士康）+ 4 个 Supplier（索尼半导体、瑞萨、村田、泰科）

### 4.3 导入商品

同上，数据类型选 **Item**，上传 `data/Item.csv`，导入 **8 个产品**。

> 注意 `trackItem` 列全部为 `False`：本课程**不启用库存跟踪**，聚焦 AR/AP 资金流。库存成本结转（COGS）是另一个大话题，第 7 课会说明真实 ERP 怎么处理。

### 4.4 导入税率

数据类型选 **Tax**，上传 `data/Tax.csv`，导入 2 条：`增值税-销项 13%`（挂 Output Tax）、`增值税-进项 13%`（挂 Input Tax）。

> 如果导入报错提示找不到科目，回到 4.1 检查科目名是否完全一致（区分大小写、无多余空格）。

### 4.5 建一个银行账户（如果第 1 课没建）

**Common → Account → New**：Name `招商银行上海分行 8888`，Parent `Bank Accounts`，Account Type `Bank`。

## 五、代码导读

| 文件（相对 `vendor/frappe-books/`） | 看点 |
|------|------|
| `models/baseModels/Party/Party.ts` | Party 用 `role` 字段区分 Customer/Supplier——一个表两种角色，和 ERPNext 的设计一样 |
| `models/baseModels/Item/Item.ts` | 商品上挂着默认收入/费用科目，开票时自动带出 |
| `models/baseModels/Tax/Tax.ts` | 税率是主表 + `TaxDetail` 子表（一个税率可含多个税目），对应 `data/Tax.csv` 里的 `TaxDetail.account` 写法 |
| `src/importer.ts` | 通用 CSV 导入器：先解析表头三行（显示名/字段名/字段名），再逐行 `getNewDoc` 走完整的校验逻辑——**导入和手工录入走同一套模型校验**，这是好设计 |

## 七、练习

财务部提了个需求："应收报表想按行业分析客户，比亚迪和立讯算 3C 行业，宁德时代算锂电行业。"

思考：这个需求应该动主数据还是动业务单据？如果要支持，你会在 Party 上加什么字段？

<details><summary>参考思路</summary>

动主数据：给 Party 增加"行业"维度（自定义字段或分组字段）。业务单据一行不用改，报表按新维度 group by 即可。这就是"维度挂在主数据上"的威力——也是你设计开票报表表结构时的核心决策。
</details>
