# 第 7 课 · 期末结账与三大报表：财务月底到底在忙什么

> 覆盖业务：期末核对（3 月 31 日结账）
> 目标：把整月 12 笔业务汇总成三张报表；理解试算平衡为什么是"结账前的总校验"；拿到全套**标准答案**核对你的账。

---

## 一、业务场景

3 月 31 日晚上 8 点，财务部灯火通明。老板等着三个数开会：**这个月赚了多少？公司现在有多少家底？别人欠我们/我们欠别人的分别是多少？**

你的任务：把 3 月的账"结"掉，出三张报表。但出报表之前，必须先过一关——**试算平衡**。

## 二、为什么有这个东西

### 2.1 试算平衡：借贷铁律的总校验

第 1 课说过：每笔分录借方合计 = 贷方合计。那么**全月所有分录加起来**，借方总和必然 = 贷方总和。结账前先把每个科目的余额列出来汇总——如果两边不等，说明某笔账记错了，**报表没有出的资格**。这就是试算平衡表（Trial Balance）：财务系统的"编译检查"。

### 2.2 三张报表是同一个恒等式的三种视角

```
                 ┌─ 试算平衡表：所有科目余额清单（校验用，对内）
所有分录汇总 ──→ ├─ 利润表：收入 − 费用 = 利润（经营成果，一段期间）
                 └─ 资产负债表：资产 = 负债 + 权益（财务状况，一个时点）
```

- **利润表（P&L）**回答"这个月干得怎么样"——损益类科目的期间发生额
- **资产负债表（Balance Sheet）**回答"公司现在什么样"——资产/负债/权益类科目的期末时点余额
- 利润表的最终利润会滚入资产负债表的权益（未分配利润），两表由此勾稽

### 2.3 为什么"结账"是个仪式

结账（Closing）= 宣布"3 月的账到此为止，不许再动"。配合第 6 课的"已提交不可改"，保证了每个期间的报表**永远稳定**——税务申报、审计、经营会引用的数字才不会"昨天和今天不一样"。ERP 系统（包括你公司的）通常有"会计期间关闭"功能，关闭后该期间禁止过账。

### 2.4 本课程的简化声明（重要）

为了让零基础聚焦 AR/AP 主线，本课程做了两个简化，真实工作里你会遇到完整版：

1. **采购直接进成本**：我们把采购的 202,000 直接计入主营业务成本。真实 ERP 会先入库存科目，销售时按出库成本结转 COGS（存货核算是一整个子模块）。
2. **增值税未做月末结转**：我们把进项/销项分挂两个科目。实务中月底要把它们对冲转入"未交增值税"科目，次月申报缴纳（112,242 = 138,502 − 26,260）。

## 三、财务在干嘛：月底结账清单

1. 检查当月所有单据是否已提交（草稿单据不入账！）
2. 银行对账（第 5 课的三类对账之一，本课程略）
3. 计提与调整分录（折旧、坏账准备等，本课程无）
4. **跑试算平衡表，借贷必须相等**
5. 出利润表、资产负债表
6. 关闭会计期间

## 五、代码导读

| 文件（相对 `vendor/frappe-books/`） | 看点 |
|------|------|
| `reports/TrialBalance/` | 试算平衡：对 AccountingLedgerEntry 按科目 group by + sum，算借/贷余额 |
| `reports/ProfitAndLoss/` | 利润表：只取损益类（Income/Expense）科目的**期间发生额** |
| `reports/BalanceSheet/` | 资产负债表：只取资产/负债/权益类科目的**期末累计余额**——注意"发生额"与"余额"的口径差异，这是报表开发最容易犯的错 |
| `reports/AccountReport.ts`、`reports/Report.ts` | 报表基类：filters → query → columns/rows 的标准流水线 |

程序员视角总结：**三张报表是同一张台账表的三种 group by**。台账设计得好（科目、期间、往来单位维度齐全），报表就是查询；台账设计得烂，报表就是灾难。你评估自己系统的报表性能问题时，先看底层台账结构。
