# 第 6 课 · 红冲与更正：为什么财务系统不让你删数据

> 覆盖业务：#11 比亚迪退货 20 个传感器
> 目标：理解红冲（反向冲销）的必要性；掌握退货单操作；建立"账务数据只增不改"的审计思维。

---

## 一、业务场景

**3 月 27 日**：比亚迪质检发现 500 个 PZ-G102N 里有 20 个响应距离不达标，要求退货。商务同意了。

仓库把货收回来，销售说："那张发票改一下呗，500 改成 480 不就行了？"

如果你真把发票改了，会发生什么：

- 3 月 2 日~27 日之间，所有读过这张发票的报表（销售月报、应收余额、销项税）**历史数字全部悄悄变化**
- 比亚迪 3 月 20 日那笔 40 万付款的分摊基准变了
- 已申报/已对账的数据和系统对不上
- 最坏情况：有人悄悄改发票给自己谋利，无人察觉

**所以全世界的财务软件有个共同禁令：已过账的单据，不许改、不许删。**

## 二、为什么有这个东西

### 2.1 审计留痕：账务数据是"append-only"的

回忆第 1 课：Submit 之后单据锁定。那业务真的变了怎么办？答案：**用一张新的反向单据，把旧单据的效果"冲掉"，两笔都留在账上。**

这就是**红冲**（红字冲销，中国财务术语；英文叫 Credit Note / Reverse Entry）：

```
原始发票（蓝字）：        红字发票（红字）：
借：应收账款   723,200    借：主营业务收入    25,600
  贷：收入      640,000    借：应交税费-销项   3,328
  贷：销项税     83,200      贷：应收账款      28,928
```

红字发票本质是一张**金额为负的销售发票**，分录方向与开票完全相反。两笔单据叠加的净效果 = "卖了 480 个"，但账上留下了完整的故事：先卖 500、后退 20、何时退、为什么退。

### 2.2 为什么不能用"反向删除"

程序员的第一反应可能是：加个 `deleted` 标记，软删除嘛。区别在哪？

| | 软删除/直接修改 | 红冲 |
|---|---|---|
| 历史报表 | 数字悄悄变化，无法解释 | 每个期间的数字都稳定且可解释 |
| 税额归属期间 | 混乱（3 月的税被 4 月改了？） | 清晰：红冲落在退货发生的期间 |
| 审计 | 无法回答"3 月 27 日发生了什么" | 完整事件链 |
| 内控 | 任何人可悄悄抹掉交易 | 红冲本身也是单据，也要审批 |

一句话：**财务系统记录的不是"现在的状态"，而是"全部历史"**。状态由历史推导，历史不可篡改。这和事件溯源（Event Sourcing）是同一个思想——AccountingLedgerEntry 表只 INSERT 不 UPDATE/DELETE，就是证据。

### 2.3 中国的特殊要求：红字发票还要对税务系统交代

在中国，增值税专用发票一旦开出并交付，退货时不能"收回作废"那么简单（跨月更不行），必须开具**红字增值税专用发票**并在税务系统备案。你做的开票模块大概率要和税控/电子发票平台对接这个流程。Frappe Books 的退货单就是红字发票的账务原型。

## 三、财务在干嘛

3 月 27 日财务动作：

1. 审核退货审批（业务前置流程）
2. 找到原发票 SINV-2026-001，**从原单生成退货单**（关联关系必须保留！）
3. 退货数量 20，系统按原单价自动计算：20 × 1,280 = 25,600 + 销项税 3,328 = 28,928
4. 提交退货单 → 应收减少 28,928，收入和销项税同步冲减

退货后 SINV-2026-001 的实际债权：723,200 − 400,000（已收）− 28,928（退货）= **294,272.00**

## 四、动手操作

### 4.1 开出退货单（红字发票）

1. 打开已提交的 SINV-2026-001（比亚迪）
2. 找到 **Make Return / 退货** 按钮（不同版本可能叫 Return 或 Credit Note，通常在已提交发票的操作菜单里）
3. 系统生成一张**数量为负**的销售发票草稿：把退货行数量设为 `-20`（即退回 20 个），单价保持 1,280，税率保持销项 13%
4. 核对：不含税 **-25,600**，税额 **-3,328**，合计 **-28,928.00**，`isReturn` 标记为真
5. Date 选 `2026-03-27`，Save → Submit

### 4.2 验证三件事

1. **应收账款**：General Ledger 查 Debtors，比亚迪相关余额 = 723,200 − 400,000 − 28,928 = **294,272.00**
2. **收入**：Sales 科目贷方余额 = 640,000 + 195,000 + 256,000 − 25,600 = **1,065,400.00**
3. **销项税**：Output Tax 贷方余额 = 83,200 + 25,350 + 33,280 − 3,328 = **138,502.00**

### 4.3 回到第 5 课复算账龄

现在第 5 课 4.3 的账龄表正式生效：比亚迪逾期部分应为 **294,272.00**（账龄 1-30 天）。Debtors 科目总余额应为 **483,552.00**（含富士康预收 -100,000）。

## 五、代码导读

| 文件（相对 `vendor/frappe-books/`） | 看点 |
|------|------|
| `models/baseModels/Invoice/Invoice.ts` | `isReturn` 标志与退货校验：退货数量不得超过原发票可退数量——找一找这个校验逻辑 |
| `models/baseModels/AccountingLedgerEntry/AccountingLedgerEntry.ts` | 观察退货单生成的分录：方向与开票相反，但同样是 append-only 写入 |
| `models/Transactional/` | 事务性单据的公共行为（提交、取消、冲销）集中在这里 |

重点思考：退货单和原发票的**关联字段**（referenceDoc / returnAgainst 一类）是数据模型的关键——没有它，"这张红字发票冲的是哪张蓝字发票"就无从回答，税务稽查时无法自证。你们开票报表里"红冲率""退货原因分析"这类指标，全都依赖这个关联。
